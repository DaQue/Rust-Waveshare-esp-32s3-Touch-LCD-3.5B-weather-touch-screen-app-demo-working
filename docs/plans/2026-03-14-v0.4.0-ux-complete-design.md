# v0.4.0 — UX Complete Design

Date: 2026-03-14
Status: Approved, awaiting v0.3.6 burn-in before implementation

---

## Theme

Make the device feel finished. Everything visible and touchable works correctly in both
orientations. Common settings are accessible without a serial cable. No dead-ends or
placeholder layouts.

## Scope

Three deliverables in priority order:

1. **Portrait parity** — all weather views fully correct in portrait (320×480)
2. **Settings view** — on-device touch UI for units and orientation lock
3. **Colors** — tuned against live hardware post v0.3.6 flash (iterative, no code design needed)

Out of scope: text entry, credentials UI, brightness control, new sensors, OTA.

## Deliverable 1: Portrait Parity

### Views requiring work

**NOW view (primary)**
New layout — three stacked cards:

```
┌──────────────────────────────┐  y=0..30    header (time | city | WiFi RSSI)
├──────────────────────────────┤  y=30       header line
│  [icon80]   72°F  ↑          │
│             FEELS 69°        │  y=36..192  weather card (156px)
│             Partly Cloudy    │
│  (tap hint)                  │
├──────────────────────────────┤
│  Indoor  71.4°F  43% RH      │  y=198..258  indoor card (60px)
│  1009 hPa   3h: +1.2         │
├──────────────────────────────┤
│  Mon  [icon]  39°  Clear     │
│  Tue  [icon]  58°  Rain      │  y=264..460  forecast card (4 rows, ~49px each)
│  Wed  [icon]  52°  Clouds    │
│  Thu  [icon]  45°  Drizzle   │
└──────────────────────────────┘  y=460..480  nav hint
```

Indoor gets its own card (not crammed into the weather card as in landscape).
Each forecast row is a single line: Day + 36px icon + temp (PROFONT_18) + condition word.

**Forecast rows — condition word**
`ForecastRow` needs a new `condition: String` field populated from OWM `weather[0].main`
(e.g. "Clear", "Clouds", "Rain", "Drizzle", "Snow", "Mist", "Thunderstorm").
This field also enriches the landscape forecast columns once it exists.

**Forecast view portrait**
Day-row list and hourly drill-down need verification and layout fixes in portrait.
Currently coded but untested.

**Indoor view portrait**
Sensor graphs (temp/humidity 24h/2h) — verify axis labels and graph bounds don't clip.

**PressureHvac view portrait**
Pressure graph + HVAC status box — likely needs layout rework for tall narrow canvas.

**Nav/system views (secondary audit)**
NavMenu, HVAC, WifiScan, I2cScan, About — simpler card layouts, lower risk.
Audit each, fix any portrait clipping or overflow.

### Portrait pixel rules (established in v0.3.6)

From profont actual metrics:

| Font         | w×h   | baseline (from cell top) |
|-------------|-------|--------------------------|
| PROFONT_10  | 6×12  | 9                        |
| PROFONT_12  | 7×15  | 11                       |
| PROFONT_14  | 10×17 | 13                       |
| PROFONT_18  | 12×22 | 17                       |
| PROFONT_24  | 16×29 | 24                       |

`Text::new` y = alphabetic baseline. Cell top = y − baseline_from_top.
All text cell tops must be ≥ card inner top (card_y + border_width).

## Deliverable 2: Settings View

### Navigation

Added to the end of the System group:
`I2cScan ↔ WifiScan ↔ About ↔ Settings`

No new entry points required — reachable by swiping through System group or via NavMenu.

### Layout (landscape and portrait)

```
┌────────────────────────────────────┐
│  ⚙ Settings              [header] │
├────────────────────────────────────┤
│                                    │
│  Temperature Units                 │
│  [ °F  ✓ ]  [  °C  ]             │
│                                    │
│  Orientation                       │
│  [ Auto ✓ ]  [ Landscape ]        │
│                                    │
│  (console: wifi set, api set-key)  │
└────────────────────────────────────┘
```

### Controls

| Setting | Options | NVS key |
|---------|---------|---------|
| Temperature units | °F / °C | existing celsius pref |
| Orientation mode | Auto / Landscape lock | existing orientation_mode |

### Behavior

- Tap a button → immediate effect + NVS save (same pattern as existing celsius pref)
- Active option: highlighted card fill + border color
- Inactive option: dim fill, no border
- Console hint at bottom ("wifi set, api set-key via serial") — discoverability without text entry
- No explicit Save button — changes apply on tap

### AppState changes

None needed for the two settings — `use_celsius` and `orientation_mode` already exist.
The view only needs tap handlers that toggle these fields and set `save_celsius_pref = true`
or the equivalent for orientation mode.

## Console Commands: Developer vs End-User

The serial console (`minicom -D /dev/ttyACM0 -b 115200`) has commands at two levels:

**End-user commands** (anyone running the firmware):
- `wifi set / show / scan / clear` — configure network
- `api set-key / set-query / show / clear` — configure OpenWeather
- `units f|c|show` — temperature units
- `orientation auto|landscape|portrait / flip` — display orientation
- `alerts on|off / beep on|off / auto-scope on|off` — alert preferences
- `alerts test warning` — verify alert display/sound works
- `status`, `about`, `version`, `reboot`, `history save`

**Developer-only commands** (fork maintainer / author):
- `alerts ua <user-agent>` — sets the NWS API User-Agent header. NWS policy requires
  this to identify the *application author*, not the end user. Default is baked into
  `src/config.rs` → `DEFAULT_NWS_USER_AGENT`. **If you fork this firmware, change the
  contact address there** — NWS will use it to reach you if your device is misbehaving.
  Location: `src/config.rs` line ~37. Format: `appname/version (email@example.com)`
- `alerts scope <scope>` — override NWS zone scope (default `area=MO`); normally
  auto-discovered via `alerts auto-scope on`
- `alerts zone show|clear` — inspect/clear cached NWS zone
- `secrets show / seed-local` — manage compile-time credential fallback
- `log quiet | log verbose` — change ESP-IDF log level (debug use)
- `debug <module>|on|off / show` — toggle per-module debug logging
- `imu read`, `i2c scan` — hardware diagnostics
- `beep advisory|watch|warning|stop` — speaker test
- `flash show / set-time` — flash metadata
